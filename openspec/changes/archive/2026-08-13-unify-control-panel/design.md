## Context

前端全部集中在 `templates/index.html` 一個檔案（標記、樣式、腳本都在裡面）。目前浮在地圖之上的操作元件分成三組獨立的絕對定位容器，各自用固定的像素偏移排列：

- 按鈕群（設定 GPS 位置、沿路走到這裡、停止移動、置中標記）位於左下。
- 多座標移動面板（座標輸入、開始移動、錯誤訊息、進度顯示、裝置寫入警示）位於左側、按鈕群上方。
- 兩個速度控制方塊（自動移動速度、搖桿速度）位於右側，彼此以固定偏移上下排列。
- 搖桿位於右下。

三項既有約束影響本次設計：

1. **前端腳本以元件識別碼取用十九個元件**。腳本的頂層敘述一旦拋錯，其後的所有頂層敘述都不執行 —— 前一個變更就是因為函式庫載入失敗觸發這個模式，導致速度標籤空白、座標讀數留在佔位符號、搜尋框 Enter 鍵失效三個看似無關的症狀。版面重組是最容易重新引入這種故障的操作。
2. **速度標籤與座標讀數在腳本開頭就由控制項推導**（見 `page-initialization` 規格）。這段初始化排在任何第三方函式庫之前，重組不得改變這個先後順序。
3. **搖桿容器必須保留既有的尺寸、位置與 CSS 類別名稱**（見 `joystick-control` 規格），且函式庫失效時會在同一個容器內顯示不可用提示。

## Goals / Non-Goals

**Goals:**

- 讓使用者在單一位置完成「設定時速 → 輸入座標 → 開始移動」的完整流程，不必在畫面兩側來回移動。
- 讓面板在任何視窗高度下都完整可用，不裁切、不溢出、不與其他元件重疊。
- 讓使用者能在需要看地圖或拖曳標記時把面板收起來。
- 重組不改變任何既有功能的行為。

**Non-Goals:**

- **不改動搖桿本體的位置、尺寸與類別名稱**。速度滑桿是設定、搖桿是持續性的拇指操作，兩者最佳位置不同。
- **不使用 HTML `<form>` 元素**。現有送出全走非同步請求，沒有表單提交流程。
- **不改變任何控制項的行為、參數或送出內容**。本次只搬移與重組版面，功能邏輯一行都不動。
- **不改動後端**。`app.py` 不在本次範圍內。
- **不改動頂部搜尋列與底部狀態列**。兩者已橫跨畫面寬度，不屬於浮在地圖上的散落元件。
- **不做面板位置的使用者自訂或拖曳**。面板固定在左側。
- **不做面板狀態的持久化**。收起／展開的狀態僅存在於當前頁面，重新載入回到展開。

## Decisions

### 以單一左側面板取代三處分散的容器

三組容器合併為一個容器，內部以四個有標題的區段組織。區段順序按實際使用流程排列：位置 → 速度 → 多座標依序移動 → 單點沿路。速度排在多座標之前，因為時速是開始移動前要先決定的參數。

替代方案是保留右側速度滑桿只整理左側，改動最小，但沒有解決使用者提出的核心問題。

### 用帶區段標題的容器，不使用 HTML `<form>` 元素

現有的送出行為全部透過非同步請求完成，沒有任何表單提交流程。使用 `<form>` 需要額外攔截預設提交行為，否則在輸入元件中按 Enter 會觸發整頁重載，把使用者填好的座標清單清空。視覺上的「表單感」由區段標題與間距達成，不需要 `<form>` 語意。

### 面板高度以視窗為上限，超出時內部捲動

四個區段合計約 480 像素高。扣掉頂部搜尋列與底部狀態列後，視窗高 600 像素時只剩約 518 像素可用，餘裕很小；再小就會溢出。

面板高度設為以視窗高度扣除頂部與底部列後的上限，內容超出時在面板內部捲動。這同時解決了原本各容器以固定像素偏移堆疊、視窗變矮就互相重疊的問題 —— 該問題在前一個變更中被明確列為範圍外。

替代方案是依視窗高度自動隱藏部分區段，但那會讓功能在小視窗上直接消失，比捲動糟。

### 收起時元件保留在文件中，只隱藏面板內容

收起以切換面板的樣式狀態實作，被收起的區段內容從畫面上隱藏但仍留在文件中。這一點是必要的而非偏好：腳本在啟動時就會讀取速度控制項來推導標籤與內部速度值，移動期間的輪詢也會持續寫入進度與裝置寫入警示這兩個顯示元件。若收起等於從文件移除，這些取用會取到空值並在執行期拋錯，重現前一個變更修掉的故障模式。

面板標題列在收起狀態下維持可見，使用者才能再次展開。

### 收起狀態下裝置寫入失敗仍然看得見

`device-location-sync` 規格要求移動期間裝置寫入失敗必須顯示給使用者。若警示只出現在面板內，面板收起時這個要求就落空。

現有實作在更新面板內警示的同時，也會更新底部狀態列的連線指示與文字（把指示燈的連線狀態移除、文字改為裝置寫入失敗）。底部狀態列不在面板內，因此收起面板不影響它。本次設計刻意依賴這個既有行為來滿足規格，並在規格中明確記錄這個情境，避免日後有人把底部狀態列的更新當成多餘而移除。

### 搖桿本體維持在右下角

搖桿是持續性的拇指操作元件，最佳位置在右下；速度滑桿是一次性設定，屬於面板。把搖桿一起移到左側可以做到「全部在左邊」的字面要求，但會與面板搶空間，且對右手持機的使用者不好按。

搖桿容器的尺寸、位置與 CSS 類別名稱完全不動，連帶保留函式庫失效時在該容器內顯示不可用提示的行為。

### 重組不改動腳本取用的元件識別碼

腳本以識別碼取用十九個元件。任一個對不上，該次取用會回傳空值並在執行期拋錯，讓其後的頂層敘述全部不執行。

因此本次把「腳本中每一處識別碼取用都必須解析成功」當成硬性契約，並以自動比對作為驗收手段：從標記中收集所有宣告的識別碼、從腳本中收集所有取用的識別碼，取差集必須為空。純粹用於阻擋事件傳播的容器識別碼允許改名，前提是腳本中對應的取用一併更新且比對仍為空。

## Implementation Contract

#### 行為

**面板組成與位置**

- 畫面左側存在單一控制面板，內含四個有標題的區段，順序為：位置、速度、多座標依序移動、單點沿路。
- 位置區段包含設定 GPS 位置與置中標記兩個按鈕。
- 速度區段包含自動移動速度滑桿與搖桿速度滑桿，各自帶標籤與數值顯示。
- 多座標依序移動區段包含座標輸入區、開始移動按鈕、錯誤訊息、進度顯示、裝置寫入警示。
- 單點沿路區段包含沿路走到這裡與停止移動兩個按鈕。
- 畫面右側不再有任何速度控制方塊。
- 搖桿維持在右下角，位置、尺寸與 CSS 類別名稱與變更前一致。

**收起與展開**

- 面板標題列提供收起／展開切換，切換後狀態立即反映在畫面上。
- 收起狀態下面板標題列仍可見，且可再次展開。
- 收起狀態下面板內的元件仍存在於文件中，腳本對它們的取用仍然成功。
- 收起狀態下若移動期間發生裝置寫入失敗，底部狀態列仍顯示裝置寫入失敗。
- 重新載入頁面後面板回到展開狀態。

**尺寸與捲動**

- 面板高度不超過視窗可用高度，內容超出時在面板內部捲動。
- 任何視窗高度下面板都不溢出畫面，且面板底部的元件都可被捲動到並操作。
- 面板不與底部狀態列或搖桿重疊。

**功能保持不變**

- 重組後每一個控制項的行為與變更前一致：設定 GPS 位置、置中標記、沿路走到這裡、停止移動、開始移動、兩個速度滑桿、座標輸入與解析、進度顯示、裝置寫入警示。

#### 介面與資料形狀

- 腳本取用的元件識別碼全部保持不變。判定方式：標記中宣告的識別碼集合必須涵蓋腳本中所有識別碼取用，差集為空。
- 純粹用於阻擋事件傳播的容器識別碼允許改名，前提是腳本中對應的取用一併更新，且上述差集仍為空。
- 搖桿容器的 CSS 類別名稱不變，函式庫失效時附加的不可用狀態類別名稱也不變。
- 速度標籤與座標讀數的初始化仍在腳本開頭、任何第三方函式庫初始化之前執行。
- 送往後端的請求內容與端點完全不變。

#### 失敗模式

- **視窗過矮**：面板內部捲動，不隱藏區段、不裁切內容。
- **收起狀態下移動中裝置寫入失敗**：面板內警示照常更新（僅未顯示），底部狀態列顯示裝置寫入失敗，因此使用者仍可察覺。
- **識別碼在重組中遺漏**：屬於實作缺陷而非執行期可接受狀態，必須在驗收的識別碼比對中被攔下，不得帶入完成。

#### 驗收標準

專案無自動化測試，以下為可重現的手動與腳本化驗證步驟。

1. **面板位置與區段**：載入頁面，確認左側單一面板依序出現位置、速度、多座標依序移動、單點沿路四個帶標題的區段，且畫面右側不再有速度控制方塊。
2. **搖桿位置不變**：確認搖桿仍在右下角，且其容器的 CSS 類別名稱、寬高與距邊距離與變更前一致。
3. **識別碼比對**：以腳本從標記中收集所有宣告的識別碼、從內嵌腳本中收集所有識別碼取用，確認取用減宣告的差集為空。
4. **腳本語法與啟動**：確認內嵌腳本可被解析，且以替身環境執行整段腳本後速度標籤顯示數值、座標讀數顯示數值、搜尋鍵綁定成立。
5. **收起與展開**：按下切換鈕確認面板內容隱藏且標題列仍可見；再按一次確認完整還原。
6. **收起狀態下元件仍可取用**：在收起狀態下啟動一次多座標移動，確認移動正常進行、展開後進度顯示為正確的座標序號，且主控台沒有取用空值造成的錯誤。
7. **收起狀態下裝置寫入失敗可見**：在收起狀態下啟動移動並使裝置不可用，確認底部狀態列顯示裝置寫入失敗。無實體裝置時此項無法執行，須記錄為未驗證。
8. **矮視窗捲動**：把瀏覽器視窗高度縮到約 600 像素，確認面板不溢出畫面、可在面板內捲動、且最下方的按鈕可被捲到並按下。
9. **功能回歸**：依序操作設定 GPS 位置、置中標記、兩個速度滑桿、座標輸入與開始移動、停止移動、沿路走到這裡，確認每一項行為與變更前一致。
10. **座標解析回歸**：重跑 `auto-walk` 規格中座標解析與驗證的全部案例，確認結果不因版面重組而改變。

#### 範圍邊界

**在範圍內：**

- `templates/index.html`：控制面板容器與四個區段的標記與樣式、兩個速度控制方塊由右側移入面板、按鈕群與多座標面板併入面板、收起／展開切換的標記與行為、面板高度上限與內部捲動、事件傳播阻擋改套用於新的面板容器。

**在範圍外：**

- 搖桿本體的位置、尺寸與類別名稱。
- 任何控制項的行為、參數或送出內容。
- `app.py` 與所有後端行為。
- 頂部搜尋列與底部狀態列的版面。
- 面板位置自訂、拖曳、以及收起狀態的持久化。
- 主 specs 中四個 capability 的 Purpose 段落（歸檔時留下的待補項，屬獨立範圍）。

## Risks / Trade-offs

- **版面重組最容易遺漏元件識別碼** → 以自動化的識別碼差集比對作為驗收項，而非靠肉眼檢查。差集不為空即視為未完成。
- **收起面板會讓面板內的裝置寫入警示看不到** → 依賴既有的底部狀態列同步更新，並在規格中明確記錄該情境，避免日後被誤刪。無實體裝置時此項無法驗證，須記錄為未驗證。
- **面板約 240 像素寬會遮住左側地圖** → 這正是加入收起功能的理由；使用者要拖曳標記或點選目的地時可先收起。
- **面板內部捲動可能讓使用者看不到下方區段的存在** → 區段順序按使用流程排列，最常用的位置與速度在最上方；捲動條本身即為可捲動的視覺提示。
- **靜態比對與替身執行無法取代一次真實頁面載入** → 沿用前一個變更的教訓。第 1、2、5、6、8、9 項驗收必須在真實瀏覽器中觀察，不得以自動化比對結案。

**實作後的驗收結果紀錄（歸檔前補入）**：

- 第 3、4、10 項以腳本驗證通過：識別碼差集為空（宣告 22 / 取用 20）、內嵌腳本語法通過、僅依賴 DOM 的初始化仍排在第三方函式庫之前、座標解析七個案例結果未變。
- 第 1、2、5、6、8、9 項由需求提出者在真實瀏覽器中確認通過。
- **第 7 項未驗證**：收起面板時裝置寫入失敗是否確實透過底部狀態列呈現，需要實體 iOS 裝置與裝置隧道服務才能觸發真實的寫入失敗，環境不具備，因此對應的任務保留為未完成。替身環境已驗證該路徑的邏輯（面板收起時底部狀態列文字變為裝置寫入失敗、連線指示燈的連線狀態被移除、面板內警示仍保有內容只是未顯示），但這不等於真實裝置上的觀察。若日後在收起面板的長程移動中發現裝置位置凍結而介面無提示，這一項就是要回頭確認的地方。
