## 1. 前端函式庫守衛與初始化順序

- [x] 1.1 依「搖桿可用性檢查與地圖初始化解耦」決策，把搖桿的可用性檢查與不可用提示移到地圖初始化之前，且該段程式不引用地圖函式庫的任何符號；地圖相依的手勢傳播阻擋（搖桿容器與控制面板各一次）留在地圖初始化成功的分支內。完成後可觀察到：搖桿函式庫載入失敗時的頁面行為與本變更前完全相同。驗證：以瀏覽器開發者工具的網路封鎖功能擋下 nipplejs 的網址後重新載入，確認搖桿容器顯示「搖桿不可用」、座標讀數與速度標籤有值、搜尋框 Enter 可用、多座標移動控制項可操作。
- [x] 1.2 依「地圖函式庫失效時採明確告知，不做假降級」決策，在建立地圖之前檢查地圖函式庫的全域物件存在、且建立過程不拋錯；任一條件不成立就在地圖區域顯示訊息指出地圖、標記與移動功能不可用，並跳過其後所有地圖相依的初始化。完成後可觀察到 `Map library failure disables map-dependent controls and preserves document-only features` 的「Map area names what is unavailable」情境。驗證：封鎖 Leaflet 的網址後重新載入，確認地圖區域出現該訊息、主控台有一則具名錯誤且沒有未捕捉的例外。
- [x] 1.3 依「地圖不可用時停用相依控制項並保留純 DOM 功能」決策，地圖不可用時將設定 GPS 位置、置中標記、開始移動、停止移動、沿路走到這裡五個控制項設為停用；在停用邏輯處以註解寫明這份清單的判準是「行為是否觸及地圖或標記物件」。完成後可觀察到：這五個控制項呈停用外觀，按下不送出任何請求也不產生執行期例外。驗證：封鎖 Leaflet 後重新載入並依序點擊這五個控制項，確認開發者工具的網路面板沒有新請求、主控台沒有新錯誤。
- [x] 1.4 依「地圖不可用時停用相依控制項並保留純 DOM 功能」決策，讓搜尋在地圖不可用時仍可運作：送出查詢與列出結果不變，選取結果時更新記憶體中的座標值與座標讀數，並跳過標記與地圖視野的更新。完成後可觀察到 `Map library failure disables map-dependent controls and preserves document-only features` 的「Search still works without the map library」情境與其範例。驗證：封鎖 Leaflet 後搜尋一個地點並選取結果，確認座標讀數更新為該結果的座標且主控台無錯誤。
- [x] 1.5 核對 `Third-party library load failure is surfaced` 要求的獨立性條款：兩個函式庫的可用性各自判定，任一個的失敗不遮蔽另一個的失敗回報。驗證：依該要求範例表的四種組合逐一封鎖網址並重新載入，確認地圖區域與搖桿容器的呈現與表格四列完全相符。

## 2. 裝置寫入結果的回報

- [x] 2.1 依「裝置寫入失敗原因對齊後端既有欄位名」決策，讓單點座標寫入失敗時，底部狀態列顯示後端回應中實際攜帶的失敗原因，僅在取不到原因時才退回固定文字；後端回應形狀不變。完成後可觀察到：未連接裝置時按下「設定 GPS 位置」，狀態列顯示具體原因而非「未連接裝置」。驗證：在未啟動 tunneld 的情況下啟動伺服器並按下該按鈕，確認狀態列文字包含後端回傳的原因字串。
- [x] 2.2 依「裝置寫入結果改為三態」決策，後端走路狀態中表示裝置寫入結果的欄位改為三態：走路開始端點在回應前設為「尚未有結果」並清空失敗原因欄位，寫入完成回呼依結果覆寫為成功或失敗。完成後可觀察到：走路剛啟動時查詢走路狀態，回應的寫入結果欄位為「尚未有結果」、失敗原因為空字串。驗證：啟動一次多座標移動後立即以命令列查詢走路狀態端點，檢視回應內容。
- [x] 2.3 依「裝置寫入結果改為三態」決策，前端只在讀到明確的成功時顯示「裝置已連接」並點亮狀態圓點；讀到「尚未有結果」時顯示等待裝置回應且圓點不點亮、裝置警示區空白；讀到失敗時沿用現行的失敗顯示與原因。完成後可觀察到：多座標移動剛啟動的第一次輪詢不會宣稱裝置已連接。驗證：在未連接裝置的情況下啟動多座標移動，觀察狀態列由「等待裝置回應」轉為寫入失敗與原因。
- [x] 2.4 核對 `Device write failures are surfaced, not swallowed` 全條要求，包含新走路必須回到「尚未有結果」而不帶前一次的失敗訊息。驗證：依該要求的範例表五列逐列核對走路狀態回應與介面呈現；無實體 iOS 裝置時，涉及實際寫入成功的列須明確記錄為未驗證，不得標記為通過。

## 3. 既有問題清理

- [x] 3.1 依「搜尋結果以文字節點插入」決策，地點搜尋結果的顯示名稱改以文字內容寫入元素，座標改以資料屬性攜帶並由事件處理器讀取，不再拼接進行內事件屬性。完成後可觀察到：顯示名稱含有角括號的搜尋結果會原樣顯示為文字，不被解讀為標記。驗證：搜尋一個一般地點確認結果可正常點選；並在瀏覽器主控台以含角括號的假資料呼叫結果渲染邏輯，確認角括號顯示為文字。
- [x] 3.2 依「開發伺服器不同時開啟除錯器與對外綁定」決策，關閉 Flask 開發伺服器的互動式除錯器，維持綁定所有網路介面不變。完成後可觀察到：伺服器啟動輸出不再宣告除錯器已啟用，且觸發後端例外時回應的是簡略錯誤頁而非互動式除錯主控台。驗證：啟動伺服器檢視啟動輸出，並以缺少必要欄位的請求觸發一次後端例外檢視回應內容。
- [x] 3.3 移除前端重複宣告的搖桿速度變數與從未被讀取的走路索引變數，以及相依清單中沒有任何程式碼使用的 timezonefinder。完成後可觀察到：頁面所有既有功能行為不變，相依清單中每個套件都能在程式碼中找到使用處。驗證：以文字搜尋確認被移除的變數名稱在前端腳本中不再出現、timezonefinder 在程式碼中無引用；並重新載入頁面操作搖桿與多座標移動確認行為不變。

- [x] 4.1 執行靜態一致性檢查：頁面標記宣告的元素識別字集合，仍為腳本存取的識別字集合的超集。完成後可觀察到：沒有任何腳本存取的識別字缺少對應的標記宣告。驗證：以命令列分別取出標記中的 id 屬性與腳本中的元素取用識別字，比對兩個集合的差集為空。

## 驗證註記

驗證於 2026-08-28 執行，工具為無頭 Chrome 151（`--dump-dom` 搭配注入頁面的診斷探針）與 Flask 測試客戶端，合計 140 項斷言全數通過。

**已驗證（實機無關）**

- 函式庫四種載入組合的頁面呈現，逐格對應 `page-initialization` 的範例表。
- 地圖不可用時五個相依控制項為停用、點擊不送請求也不拋錯；搜尋與選取仍可用，並以規格範例的座標值（25.033964, 121.564468 → 25.047924, 121.517081）比對通過。
- 走路狀態三態的完整轉換序列，逐列對應 `device-location-sync` 的範例表。後端測試以 Flask 測試客戶端執行 app.py 的真實程式碼，只把裝置寫入函式替換為樁。
- 搜尋結果的顯示名稱含標記字元時原樣顯示為文字，未產生元素、未執行 onerror。
- 開發伺服器啟動輸出為 Debug mode: off，後端例外回應為簡略錯誤頁而非互動式除錯主控台。
- 既有功能回歸：座標讀數、兩個速度標籤、搖桿拖曳與放開、地點搜尋與選取、多座標移動的路線繪製與進度顯示、單點沿路移動、控制面板收起與展開。

**未驗證**

- **實體 iOS 裝置寫入成功的那一列未驗證。** 所有裝置寫入在測試中都被替換為樁，沒有任何一次寫入真的送到裝置。執行當下確實有連著的實體裝置與運作中的 tunneld，但依使用者決定不對實機進行測試，因此這一列不得視為通過。
- 連帶未驗證的是：走路期間裝置寫入由成功轉為失敗、再轉回成功的真實硬體行為；以及單點寫入在真實失敗情況下由後端產生的實際錯誤字串內容（前端顯示邏輯已以後端實際回傳的失敗形狀驗證通過）。

補作方式：在連著裝置且 tunneld 運作時，以一段短路線啟動一次多座標移動，確認底部狀態列由「等待裝置回應…」轉為「裝置已連接」並點亮圓點，再拔除裝置確認轉為「裝置寫入失敗」並帶出原因。
