## 1. 後端：保留並回報裝置身分

- [x] 1.1 讓伺服器在建立共用連線時保留該裝置的身分（udid、機型代號、機型可讀名稱、OS 版本），關閉連線時清除 —— 滿足規格需求 `The connected device's identity is retained when the connection is established`，依設計決策「裝置身分在連線時保留，不從 tunneld 清單推斷」，身分取自實際建立的那條連線，不得重新讀取 tunneld 清單再取第一筆。身分的寫入與清除須與既有的連線建立、替換、關閉流程共用同一把裝置鎖。驗證：連線後查詢身分得到非空的四個欄位；呼叫停止模擬使連線關閉後再查詢，身分為空。
- [x] 1.2 把機型代號轉成可讀機型名，代號不在對照表時回傳代號本身 —— 依設計決策「機型名用函式庫內建對照，不用 RSD 物件的名稱欄位」，對照取自 pymobiledevice3 內建的裝置表，不新增依賴；**不得**使用 RSD 物件的 name 屬性，該欄位裝的是網路介面名。驗證：以規格範例表三個代號呼叫轉換，`iPhone14,2` 得 `iPhone 13 Pro`、`iPhone10,1` 得 `iPhone 8 (Global)`、`iPhone19,1` 得 `iPhone19,1`。
- [x] 1.3 新增唯讀的 GET 端點回傳 `identity` 與 `visible` 兩個鍵 —— 滿足規格需求 `Device identity is reported without touching the device`，依設計決策「回報身分的端點完全不接觸裝置」，不得建立、替換或關閉連線，不得寫入或清除模擬定位，不得改動走路狀態，不得進入裝置鎖。驗證：連續呼叫端點一百次後，走路狀態的欄位不變、共用連線物件既未建立也未關閉（以伺服器日誌與端點回應確認）。
- [x] 1.4 讓 `visible` 為三態：udid 在 tunneld 通道清單中為 true、不在為 false、tunneld 查詢失敗為 null —— 依設計決策 —— 區分「伺服器以為連著誰」與「那支手機還在不在」——。tunneld 查詢失敗時端點仍須以成功狀態碼回應，把查不到表達為 null 而非端點自身錯誤。無保留身分時 `identity` 為 null 且 `visible` 為 null。驗證：停掉 tunneld 後呼叫端點，回應為 2xx 且 `visible` 為 null 而非 false。

## 2. 前端：狀態列與輪詢

- [x] 2.1 讓狀態列改由單一渲染函式輸出，文字由「裝置標示」與「裝置狀態」兩個模組層級變數組合而成 —— 依設計決策「狀態列由單一渲染函式擁有，文字由身分與狀態兩半組成」，既有三個直接寫入狀態列的地方（送出座標後、停止模擬後、走路輪詢中）改為只更新狀態那一半，不再自行寫入文字節點與圓點樣式。驗證：走路中發生裝置寫入失敗且已知裝置身分時，狀態列同時出現機型名與寫入失敗，兩者不互相取代。
- [x] 2.2 讓控制介面每 3 秒查詢一次身分端點並更新狀態列的裝置標示 —— 滿足規格需求 `The status bar reports which device is connected`，依設計決策「輪詢間隔 3 秒」，輪詢自頁面載入起持續進行，不因走路開始或結束而停止。輪詢只用 DOM 與 fetch，繫結須排在只依賴 DOM 的初始化區塊內，第三方函式庫載入失敗時仍須運作。驗證：故意讓地圖函式庫載入失敗，狀態列仍會定期更新。
- [x] 2.3 讓狀態列依身分與可見性呈現四種情境 —— 無身分顯示 `未連接裝置`、可見顯示 `<機型名> · iOS <版本> 已連接` 且圓點亮起、不可見顯示 `<機型名> 已離線`、無法判斷顯示 `<機型名> · 無法確認狀態`，後三者圓點熄滅。驗證：逐項比對規格需求 `The status bar reports which device is connected` 的狀態列文字範例表六列。
- [x] 2.4 讓身分查詢失敗或回應缺少必要欄位時保留既有狀態列文字，且不中斷輪詢迴圈。驗證：暫時停掉伺服器，主控台無未捕捉例外、狀態列停在最後一次成功的內容，伺服器恢復後輪詢自行接上。
- [x] 2.5 把診斷控制項的標示改成會提及連線 —— 滿足規格需求 `Diagnostics is triggerable from the control interface`，依設計決策「不新增連線端點，改為讓既有的診斷控制項名副其實」，不新增第二顆按鈕、不新增連線端點。驗證：未按下按鈕時讀其文字即可看出它會嘗試建立連線。

## 4. 診斷面板的裝置機型

- [x] 4.1 讓伺服器在取得通道裝置清單時，記錄清單中**每一台**裝置的 udid 到機型代號、機型可讀名稱與 OS 版本的對應，而不只是被選用的那一台 —— 滿足規格需求 `Model information is recorded for every device seen during a connection attempt`，依設計決策「機型對照取自既有交握的副產品，不另外連線」，不得為此額外發起任何交握；清單取得本來就會對每一筆記錄各做一次交握，這裡只是留下已經到手的欄位。機型名沿用既有的機型代號轉換函式。驗證：以兩筆通道記錄的假清單走過連線路徑後，對照中有兩筆而非一筆，且交握次數與未加此功能時相同。
- [x] 4.2 讓診斷回應的每一筆裝置項目在機型已知時另外帶有機型可讀名稱、OS 版本，以及該筆是否為目前使用中的那一台 —— 滿足規格需求 `Diagnostics reports the device records it found`。機型來源依序為目前連線身分（udid 相符時）與上述對照；兩者皆無時該筆**省略**這些欄位，不得帶空字串或猜測值。既有的 udid、介面位址、通道位址、通道埠四個欄位維持原樣回報。驗證：逐列比對該需求的範例表三種情形（使用中、已交握但非使用中、從未交握）。
- [x] 4.3 讓診斷面板的每一筆裝置呈現為兩行：第一行是機型名與 OS 版本（使用中的那一台加註記，機型未知時整行省略），第二行是既有的 udid 與介面位址 —— 依設計決策「裝置清單的機型與原始欄位分兩行，沿用既有樣式類別」，第一行不套用樣式類別、第二行維持既有的等寬小字類別，不得新增或修改任何 CSS 規則，也不得挪用階段狀態的淡化類別。驗證：以假回應渲染後，機型已知的項目有兩行、未知的只有一行且無空白行；`git diff --name-only` 的結果不含 `static/css/style.css`。
- [x] 4.4 在專案文件的主要功能說明中描述「每一台列出的裝置都顯示機型」及其零額外交握的來源，使錨點詞 `_device_models` 至少出現一次 —— 滿足規格需求 `Documentation covers every implemented feature`。文件須說明 tunneld 本身不提供機型，以及機型未知時欄位缺席而非猜測的理由。驗證：在 docs 目錄下搜尋該詞回傳至少一筆結果。

## 5. 輪詢的日誌噪音

- [x] 5.1 讓身分查詢端點的 **2xx** 回應不寫入存取日誌，其他任何狀態碼照常寫入 —— 滿足規格需求 `The identity poll does not drown the server log`，依設計決策「輪詢的成功存取日誌被濾掉，失敗仍然記錄」，判斷依據為日誌記錄攜帶的請求行與狀態碼參數，**不得**比對格式化後的整行字串（非 2xx 的訊息會被包上終端色碼）。其他路徑的日誌行為不得改變，走路進度與裝置寫入失敗的輸出不經由存取日誌、不得受影響。驗證：逐列比對該需求的範例表五列 —— 身分查詢的 200 被抑制、500 與 404 仍寫入、診斷端點與定位端點的 200 仍寫入。
- [x] 5.2 在專案文件的主要功能說明中記錄這項日誌抑制及其「只濾成功、失敗照記」的理由，使錨點詞 `_mute_poll_access_log` 至少出現一次 —— 滿足規格需求 `Documentation covers every implemented feature`。須寫出為何不採用降低輪詢頻率的做法。驗證：在 docs 目錄下搜尋該詞回傳至少一筆結果。

## 6. 可見性改為按需更新

本群組修正群組 1 交付的行為：任務 1.3 與 1.4 當時讓身分查詢端點自行查詢 tunneld，實測發現那會讓 tunneld（獨立的 uvicorn 程序，日誌與本伺服器共用同一個終端機）每 3 秒多一行。已完成的那兩項不回退，由本群組取代其查詢方式。

- [x] 6.1 讓共用連線建立時把可見性一併記為「在清單中」、連線關閉時一併清為「未知」，與身分在同一把裝置鎖之下 —— 滿足規格需求 `The connected device's identity is retained when the connection is established`。理由是能建立連線就代表剛讀到的通道清單裡有它，這個判斷免費且當下為真；沒有它，剛連上就會顯示「無法確認狀態」。驗證：以假的 RSD 走過連線路徑後可見性為 true，走過中斷路徑後為 null。
- [x] 6.2 讓身分查詢端點**不再查詢 tunneld**，改為回傳記憶體中最後一次已知的可見性 —— 滿足規格需求 `Device identity is reported without touching the device` 與 `The identity poll does not drown the server log`，依設計決策「可見性只在連線建立與診斷時更新，輪詢不查 tunneld」。三態語意不變：true 為最近一次清單中有它、false 為讀到清單但沒有它、null 為尚未判斷或最近一次讀取失敗。驗證：連續呼叫端點數十次，期間對 tunneld 的請求數為零（以替身計數確認），且回應的 `visible` 等於最後一次記錄的值。
- [x] 6.3 讓診斷端點在讀取通道清單之後更新可見性：清單中有目前身分的 udid 設為 true、沒有設為 false、清單讀取失敗設為 null —— 依設計決策「可見性只在連線建立與診斷時更新，輪詢不查 tunneld」，診斷本來就會讀清單，不新增任何查詢。無保留身分時不更新。驗證：三種 tunneld 情形各跑一次診斷後，隨即查詢身分端點得到 true、false、null。
- [x] 6.4 在專案文件的主要功能說明中更新這段行為：可見性只在連線建立與診斷時更新、身分查詢端點不碰 tunneld、以及失去自動偵測的那一種情況由裝置寫入結果補上。驗證：文件中不再宣稱身分查詢端點會查詢 tunneld，且 `_mute_poll_access_log` 與 `/api/device` 兩個錨點詞仍各至少出現一次。

## 7. 使用中標記收斂到單一通道記錄

本群組修正群組 4 交付的行為：任務 4.2 以 udid 判斷使用中，而同一支手機插線又在同一個 Wi-Fi 下時會有兩筆 udid 相同、介面名不同的通道記錄，兩筆都會被標為使用中。已完成的 4.2 不回退，由本群組收斂其判定依據。

- [x] 7.1 讓連線建立時把該次選用的通道記錄的介面名連同既有身分欄位一起記錄、中斷時一起清除 —— 滿足規格需求 `The connected device's identity is retained when the connection is established`。介面名取自通道裝置物件的名稱屬性（該屬性被填入那一筆通道記錄的介面名），不得另行推導。該欄位只供判定用途，**不得**出現在身分查詢端點的回應中。驗證：以假的通道裝置走過連線路徑後身分含介面名；查詢身分端點的回應**不含**該欄位。
- [x] 7.2 讓診斷回應的使用中標記同時比對 udid 與介面名，同一支手機的多筆通道記錄至多一筆為真；身分記錄的介面名不在任何一筆記錄中時全部為否 —— 滿足規格需求 `Diagnostics reports the device records it found`，依設計決策「使用中標記落在通道記錄上，不是落在裝置上」。機型名的判定維持只比對 udid，同一支手機的每一筆記錄都應顯示機型。驗證：逐列比對該需求的「one phone, two tunnel records」範例表三列 —— 連線用的那筆為真、同 udid 另一筆為否、介面名對不上時全為否；並確認三列的機型名皆存在。
- [x] 7.3 在專案文件的主要功能說明中記錄使用中標記以 udid 加介面名判定的理由，以及對不上時一筆都不標的降級選擇。須寫出同一支手機可能同時有 USB 與 Wi-Fi 兩筆通道記錄這個前提。驗證：文件中不再宣稱使用中僅以 udid 判定，且既有錨點詞 `_device_models` 仍至少出現一次。
